## 4. F0a/F0b 本地实现

- 单一顺序 job：install → syntax → source GScan → build → ZIP validation → generated diff → 可选 candidate upload。
- PR 只验证；`master` 仅在 theme input 变化时允许走上传步骤。
- PR 可取消旧验证；`master` 的 `cancel-in-progress` 为 `false`。
- 候选 identity 为 `ndawn-<SHA12>`；PR identity 为 `ndawn-pr-<PR>-<SHA12>`。
- staging 内改写 `package.json.name`，仓库根 `package.json.name` 保持 `ndawn`。
- 每次构建先清理旧 ZIP，`dist` 最终只能有一个 `FINAL_ZIP`。
- staging 文件时间戳固定为 UTC 2000-01-01，ZIP 输入按路径稳定排序；同一源码连续两次构建的 ZIP 逐字节一致。
- 内容断言、package identity、GScan 与 checksum 全部消费同一个 `FINAL_ZIP`；上传步骤不重新打包。
- 发布包拒绝 `.github/**`、`.tmp/**`、`docs/**`、`specs/**`、`scripts/**`、源码、依赖、锁文件及其他非 allowlist 文件。
